    HttpRestClient Class

    Namespace
    Kampute.HttpClient
    Assembly
    • Kampute.HttpClient.dll

    Definition

    Sends requests to a REST API through an HttpClient, and converts between .NET objects and HTTP content.
    public class HttpRestClient : IDisposable
    Inheritance
    • object
    • HttpRestClient
    Implements
    • IDisposable

    Remarks

    By default, every HttpRestClient uses one shared HttpClient, so clients created for different APIs reuse the same connections. A client can also use an HttpClient that the application creates and configures.

    DefaultRequestHeaders apply to every request of the client. BeginHeaderScope(IEnumerable<KeyValuePair<string, string>>) and BeginPropertyScope(IEnumerable<KeyValuePair<string, object>>) add or override headers and request properties until the scope is disposed, without changing the defaults.

    ContentFormatters read response content into .NET objects by its Content-Type, and write the payloads of SendObjectAsync<T>(this HttpRestClient, HttpMethod, string, object, string, CancellationToken). When a request sets no Accept header, the client sets one from the media types the formatters can read into the expected type.

    Failures are recovered in two ways. RetryPolicy decides whether to retry after a transient connection failure or a timeout, and ErrorHandlers decide whether to retry after an error response. An error response that no handler retries is thrown as an HttpResponseException.

    BeforeSendingRequest and AfterReceivingResponse let the application change or inspect each request and response, for example to add headers or to log.

    Properties

    BaseAddress

    Gets or sets the base address of the requests.
    public Uri BaseAddress { get; set; }

    Property Value

    Uri
    The URI that relative request URIs are resolved against, or null if requests use absolute URIs.

    Remarks

    If the base address does not end with a slash, one is appended. Without it, the last segment of the path would be replaced when a relative URI is resolved: with http://example.com/api, the relative URI users would resolve to http://example.com/users instead of http://example.com/api/users.

    When the base address is null, every request must use an absolute URI.

    ContentFormatters

    Gets the content formatters that read response content and write request payloads.
    public HttpContentFormatterCollection ContentFormatters { get; }

    Property Value

    HttpContentFormatterCollection
    The mutable collection of IHttpContentFormatter instances of this client.

    Remarks

    The formatters are tried in order. The first one that can read the media type of a response into the expected .NET type reads it, and the media types they can read feed the Accept header of requests that do not set one. The first one that can write a payload in the requested media type writes the payloads of SendObjectAsync<T>(this HttpRestClient, HttpMethod, string, object, string, CancellationToken).

    The collection is empty initially. Format packages register their formatters with extension methods such as UseJson.

    DefaultRequestHeaders

    Gets the headers sent with every request of this client.
    public HttpRequestHeaders DefaultRequestHeaders { get; }

    Property Value

    HttpRequestHeaders
    The default request headers of this client.

    Remarks

    Headers of an active scope, begun with BeginHeaderScope(IEnumerable<KeyValuePair<string, string>>), override these headers.

    HttpHeaders is not thread-safe. The client locks this collection while it copies the headers into each new request, and HttpError401Handler locks it while it updates the Authorization header. Code that changes this collection while requests are in flight must lock the same object.

    Examples

    This code replaces the access token while other requests may be in flight:
    lock (client.DefaultRequestHeaders)
{
    client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue(AuthSchemes.Bearer, accessToken);
}

    ErrorHandlers

    Gets the error handlers that decide whether to retry a request after an error response.
    public HttpErrorHandlerCollection ErrorHandlers { get; }

    Property Value

    HttpErrorHandlerCollection
    The error handlers of this client.

    Remarks

    When a request receives an error response, the handlers whose IHttpErrorHandler.CanHandle(HttpStatusCode) accepts the status code are asked in the order they were added, until one of them returns a request to retry. If none does, the error is thrown as an HttpResponseException.

    ResponseErrorType

    Gets or sets the type into which the body of an error response is read.
    public Type ResponseErrorType { get; set; }

    Property Value

    Type
    The error model of the API, or null to leave the body of error responses unread.

    Remarks

    When this property is set, the client reads the body of an error response into this type with the formatters in ContentFormatters, and exposes the result through HttpResponseException.ResponseObject. If the body cannot be read, HttpResponseException.ResponseObject is null.

    When the type implements IHttpErrorResponse, the object read from the body creates the exception, so it can carry the error details of the API, such as validation errors.

    RetryPolicy

    Gets or sets the retry policy for transient connection failures.
    public IHttpRetryPolicy RetryPolicy { get; set; }

    Property Value

    IHttpRetryPolicy
    The IHttpRetryPolicy that decides whether and when a request is retried after a transient connection failure or a timeout. The default is HttpRetryPolicy.None, which does not retry; setting null restores it.

    Remarks

    The policy applies when a request fails without a response, for example because the connection is refused, reset, or closed before the response is complete, the host name cannot be resolved or the host cannot be reached, or HttpClient.Timeout elapses. Error responses, such as '503 Service Unavailable', are handled by ErrorHandlers instead.

    The limits of the policy apply to the retries after connection failures only. Error handlers count their own retries separately, so a call that fails in several ways can be retried more times in total than this policy allows.

    Examples

    This policy retries a request up to five times after connection failures, with a delay that starts at one second and doubles each time:
    client.RetryPolicy = RetryStrategies.Exponential(TimeSpan.FromSeconds(1)).WithMaxRetries(5).ToHttpRetryPolicy();

    Begins a scope that sets or removes headers of the requests this client sends until the scope is disposed.
    public virtual IDisposable BeginHeaderScope(IEnumerable<KeyValuePair<string, string>> headers)

    Parameters

    headers IEnumerable<KeyValuePair<string, string>>
    The headers to set, or, with a null value, to remove.

    Returns

    IDisposable
    An IDisposable that ends the scope when it is disposed.

    Exceptions

    ArgumentNullException
    Thrown if headers is null.

    Remarks

    The headers of the scope replace the headers of the same name in DefaultRequestHeaders. A scope flows with the asynchronous context of the code that begins it: it applies to the requests that code makes, including in methods it awaits, but not to requests made concurrently by unrelated code. Scopes can be nested, and an inner scope overrides an outer one.

    The HttpClient.DefaultRequestHeaders of the underlying HttpClient are added to a request only for the headers it does not already have, so a header that a scope removes is still sent if the HttpClient sets it. Keep the default headers of the HttpClient empty, and set them on DefaultRequestHeaders instead.

    Remarks

    The request gets the headers of DefaultRequestHeaders, overridden by the headers of the active scopes. If neither sets an Accept header, it gets one with the media types that ContentFormatters can read into responseObjectType and into ResponseErrorType, or */* if responseObjectType is null.

    The request gets the properties of the active scopes, and the following properties:

    • HttpRequestMessagePropertyKeys.TransactionId– A unique identifier (Guid) of the request, which the clones made for its retries keep, so that the attempts of a call can be correlated in logs.
    • HttpRequestMessagePropertyKeys.ResponseObjectType– The .NET type (Type) expected in the response, if any.

    AfterReceivingResponse

    Occurs when an HTTP response has been received.
    public event EventHandler<HttpResponseMessageEventArgs> AfterReceivingResponse

    Event Type

    EventHandler<HttpResponseMessageEventArgs>

    Remarks

    The event is raised for every response, including error responses and responses that lead to a retry, before the client checks the status code or reads the content. Handlers can inspect or log the response.

    For requests sent with HttpCompletionOption.ResponseHeadersRead, such as those of GetAsStreamAsync(this HttpRestClient, string, CancellationToken), GetToStreamAsync(this HttpRestClient, string, Stream, CancellationToken) and DownloadAsync(this HttpRestClient, HttpMethod, string, HttpContent, Func<HttpContentHeaders, Stream>, CancellationToken), the event is raised once the headers arrive and the body is not buffered. A subscriber that reads the response content consumes the body stream, which leaves nothing for the caller.
