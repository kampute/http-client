    public sealed class XmlFormatter : HttpContentFormatter
    Inheritance
    • object

    Remarks

    The formatter also reads text/xml, which RFC 7303 registers with the same definition as application/xml, and advertises it in the Accept header. It reads any media type with the +xml structured syntax suffix, which RFC 7303 registers for XML media types, such as application/vnd.example+xml, but does not advertise it. It writes application/xml only.

    The client reads a response with the first formatter in HttpRestClient.ContentFormatters that can read it, so a formatter for a specific +xml media type takes over that type only when it is added before this one.

    The Serializer property selects the serializer. The same rule applies when a response is read, by the requested model type, and when a payload is written, by the runtime type of the payload. With the default, XmlSerializerKind.Auto, a type marked with T:System.Runtime.Serialization.DataContractAttribute or T:System.Runtime.Serialization.CollectionDataContractAttribute uses DataContractSerializer, and any other type uses T:System.Xml.Serialization.XmlSerializer.

    Register the formatter with UseXml(this HttpRestClient, Action<XmlFormatter>). Change its properties before the client sends requests, because a registered formatter is shared by all requests of the client.

    Remarks

    As RFC 7303 specifies, a byte order mark decides the character encoding of the content. Without one, the charset parameter of its Content-Type header decides it, and without either, the XML encoding declaration, or UTF-8 if there is none.
